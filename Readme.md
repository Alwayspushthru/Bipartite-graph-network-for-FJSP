# 基于二部图网络的柔性作业车间调度（FJSP）

本项目使用**二部图注意力网络 + PPO 强化学习**求解柔性作业车间调度问题（Flexible Job Shop Problem, FJSP），训练数据由程序自动生成。

---

## 项目结构

```
├── env/FJSPEnv.py          # 调度环境（状态、特征提取、步进逻辑）
├── model/
│   ├── BiGraphNetwork.py   # 二部图注意力网络（工序↔机器双向消息传递）
│   ├── ppo.py              # PPO 训练器
│   └── sub_layers.py       # MLP、Actor、Critic 子层
├── utils/
│   ├── data_utils.py       # 数据生成（SD3CaseGenerator 等）
│   └── common_utils.py     # 公共工具函数
├── train.py                # 训练入口
├── test.py                 # 测试入口
└── params.py               # 所有超参数定义
```

## 强化学习环境

### 问题定义

FJSP 由 $J$ 个工件和 $M$ 台机器组成。每个工件包含若干道工序，工序之间存在先后约束；每道工序可在多台机器上加工，加工时间因机器而异。目标是找到一个调度方案，最小化所有工件的最大完工时间（**makespan**）。

### 状态表示（EnvState）

环境状态由以下六个张量构成：

| 字段 | 形状 | 含义 |
|------|------|------|
| `fea_j_tensor` | [B, J, 6] | 工件节点特征 |
| `fea_m_tensor` | [B, M, 4] | 机器节点特征 |
| `fea_pairs_tensor` | [B, J, M, 6] | 工件-机器边特征 |
| `candidate_tensor` | [B, J] | 每个工件当前待调度的工序索引 |
| `job_mask_tensor` | [B, J] | 工件是否已全部调度完毕 |
| `dynamic_pair_mask_tensor` | [B, J, M] | (工件, 机器) 对的可行性掩码 |

其中 B 为并行环境数，J 为工件数，M 为机器数。

### 环境初始化

**输入数据**
- `job_length_list`：每个工件的工序数，形状 `[B, J]`
- `op_pt_list`：加工时间矩阵，形状 `[B, O, M]`，0 表示该工序不能在该机器上加工

**加工时间归一化**

```python
lb = 实例内所有有效加工时间的最小值
ub = 实例内所有有效加工时间的最大值
pt_norm = (pt - lb) / (ub - lb)   # 归一化到 [0, 1]
```

**关键数据结构**
- `op_valid_mask`：工序有效性掩码（区分真实工序与填充位）
- `process_relation [B, O, M]`：工序与机器的可行加工关系
- `op_ct_lb`：工序完工时间下界，沿工件工序链累积传播

### 特征工程

#### 工件特征 `fea_j` — [B, J, 6]

| # | 特征 | 含义 |
|---|------|------|
| 1 | `feasible_mas_ratio` | 可用机器数 / 总机器数 |
| 2 | `job_ready` | 工件就绪时间（当前工序最早可开始的时间） |
| 3 | `rem_ops` | 剩余工序数 / 总工序数（调度进度） |
| 4 | `rem_work` | 剩余工序平均加工时间之和（剩余工作量估计） |
| 5 | `p_mean` | 当前工序在所有可用机器上的平均加工时间 |
| 6 | `p_span` | 当前工序最大 - 最小加工时间（机器间差异度） |

所有工件特征经 z-score 标准化处理（按实例统计均值和方差）。

#### 机器特征 `fea_m` — [B, M, 4]

| # | 特征 | 含义 |
|---|------|------|
| 1 | `feasible_ops_norm` | 可处理未调度工序数 / 活跃工件数 |
| 2 | `mach_ready` | 机器下一次可用时间（空闲时刻） |
| 3 | `expect_workload` | 期望剩余负载（均匀分配假设） |
| 4 | `idle` | 机器累计空闲时间 |

#### 边特征 `fea_pairs` — [B, J, M, 6]

工件-机器对的边特征，刻画具体分配的时间特性：

| # | 特征 | 含义 |
|---|------|------|
| 1 | `pt_out` | 在该机器上的加工时间（不可行对为 0） |
| 2 | `start` | 最早开始时间 = max(工件就绪时间, 机器就绪时间) |
| 3 | `wait_job` | 工件等待机器的时间 = max(0, 机器就绪 - 工件就绪) |
| 4 | `wait_mach` | 机器等待工件的时间 = max(0, 工件就绪 - 机器就绪) |
| 5 | `ratio_mach` | 加工时间 / 该机器所有工序的平均加工时间 |
| 6 | `ratio_op` | 加工时间 / 该工序在所有机器上的平均加工时间 |

### 动作空间

**动作编码**：整数 $a \in [0,\ J \times M)$，解码方式：

```python
job     = action // n_machines
machine = action % n_machines
```

即选择"将工件 `job` 的当前候选工序分配到机器 `machine` 上加工"。不可行的 (工件, 机器) 对由网络层面掩码屏蔽（logits 置为 $-\infty$），保证采样到的动作始终合法。

### 步进逻辑（step）

```
1. 解码动作 → 确定工件与机器
2. 更新工件进度：candidate 指针指向下一道工序；若已是最后工序则标记工件完成
3. 计算时间：
     start_time = max(job_ready_time, machine_ready_time)
     end_time   = start_time + processing_time
4. 更新下界：若实际完工时间 > 理论下界，沿工序链向后传播时间差
5. 重构三类特征（工件、机器、边）
6. 终止判断：所有工序调度完毕时 done = True
```

### 奖励函数

采用**基于 makespan 下界改善的稠密奖励**：

```
reward_t = makespan_lb_before_step - makespan_lb_after_step
```

每步奖励等于该步决策带来的最大完工时间下界的减少量，避免了稀疏奖励下探索困难的问题。整个 episode 的累计奖励近似等于总的 makespan 改善量。

## 网络结构（BiGraphNetwork）

### 输入编码

```
工件特征 [B, J, 6]   ──MLP──►  工件嵌入  [B, J, 128]
机器特征 [B, M, 4]   ──MLP──►  机器嵌入  [B, M, 128]
边特征  [B, J, M, 6] ──MLP──►  边嵌入   [B, J, M, 128]
```

### 二部图注意力层（×2 层）

每层 `BiGraphLayer` 执行双向注意力消息传递：

```
工序 ← 机器（O←M）：
  Query = 工序嵌入，Key/Value = 机器嵌入
  注意力权重由边特征门控
  → 更新工序嵌入（含残差连接）

机器 ← 工序（M←O）：
  Query = 机器嵌入，Key/Value = 工序嵌入
  对无有效工序的机器特殊处理（零消息）
  → 更新机器嵌入（含残差连接）

边特征更新：
  concat(工件嵌入, 机器嵌入, 当前边嵌入) → tanh → 线性层 → 残差连接
```

### Actor 头（策略输出）

```
对工件、机器嵌入分别做全局平均池化（全局上下文向量）
→ concat(工件个体嵌入, 工件全局, 机器个体嵌入, 机器全局, 边嵌入)
→ reshape 为 [B, J×M, d]
→ 3 层 MLP（hidden=64，tanh 激活）
→ logits [B, J×M]
→ 不可行动作置 -inf → Softmax → 类别分布
```

### Critic 头（价值估计）

```
对可行边嵌入做掩码全局平均池化
→ concat(工件全局, 机器全局, 边全局)
→ 3 层 MLP（hidden=64，tanh 激活）
→ 标量价值 V(s)
```

| 特征类型 | 输入维度 | 嵌入维度 |
|----------|----------|----------|
| 工件特征 | 6 | 128 |
| 机器特征 | 4 | 128 |
| 边特征 | 6 | 128 |
| Actor/Critic 隐藏层 | — | 64 |

## 训练数据生成（SD3）

训练数据由 `SD3CaseGenerator`（`utils/data_utils.py`）在线随机生成，无需提前准备数据文件。训练规模为 10×5、10×15、20×10。

### 默认规模

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `n_j` | 10 | 作业数 |
| `n_m` | 5 | 机器数 |

### 生成规则

**① 每个作业的工序数**

从 `[floor(0.8 × n_m), ceil(1.2 × n_m)]` 范围内随机取整数。默认（n_m=5）即每个作业 **4～6 道工序**。同一批次（`num_envs=20` 个并行环境）共享同一组工序数配置，每次更新时重新采样。

**② 每道工序的可加工机器数（柔性度）**

从 `[1, n_m]` 中随机取整，再从所有机器中无重复随机抽取对应数量的机器分配给该工序。

**③ 各机器的加工时间**

先为每道工序随机生成平均加工时间 `mean = randint(1, 99)`，各兼容机器的实际加工时间在均值的 **±20%** 范围内随机取整：

```
low  = max(1,  round(mean × 0.8))
high = min(99, round(mean × 1.2))
actual = randint(low, high)
```

### 数据格式

每个实例第一行为 `作业数 机器数 平均柔性度`，后续每行描述一个作业的所有工序及其可加工机器与加工时间。

## PPO 训练流程

```
初始化：
  20 个并行训练环境 + 验证环境
  加载验证数据集
  初始化 PPO + BiGraphNetwork

每次更新（共 1000 次）：
  ├── 每 20 步：重新采样训练数据（在线生成）
  ├── 收集完整 episode（20 个并行环境同步推进）
  │     └── 每步：前向传播 → 采样动作 → 步进环境 → 记录转换
  ├── GAE 估计优势函数
  │     A_t = r_t + γ·V(s_{t+1}) - V(s_t) + γλ·A_{t+1}
  ├── PPO 4 轮小批次更新
  │     loss = policy_loss + value_loss + entropy_loss
  ├── 每 10 步：在验证集评估 makespan
  └── 保存验证集上表现最优的模型
```

### 主要超参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `num_envs` | 20 | 并行训练环境数 |
| `max_updates` | 1000 | 训练更新轮数 |
| `lr` | 3e-4 | 学习率 |
| `k_epochs` | 4 | 每轮数据的 PPO 更新次数 |
| `eps_clip` | 0.2 | PPO 裁剪参数 |
| `gamma` | 1.0 | 折扣因子（无折扣，直接优化总 makespan） |
| `gae_lambda` | 0.98 | GAE 平滑系数 |
| `reset_env_timestep` | 20 | 重新采样训练数据的间隔步数 |
| `validate_timestep` | 10 | 验证与日志记录的间隔步数 |

## 核心设计亮点

| 设计 | 说明 |
|------|------|
| **二部图结构** | 天然匹配 FJSP 中工件-机器的二部关系，比 disjunctive graph 更紧凑高效 |
| **稠密奖励** | 基于 makespan 下界改善，每步均有学习信号，避免稀疏奖励的探索难题 |
| **可行动作掩码** | 网络层面直接屏蔽不合法动作，保证采样合法性，加速收敛 |
| **在线数据生成** | 每轮重新采样训练实例，提升模型对不同规模和柔性度的泛化能力 |
| **归一化特征** | 加工时间归一化 + z-score 标准化，稳定训练、跨实例迁移 |
| **边特征双向更新** | 工件和机器嵌入同步更新边特征，保持结构一致性 |
